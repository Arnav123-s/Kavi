# Teaching through an older configuration

Author: [Arnav123-s](https://github.com/Arnav123-s)

7 September 2026. Recorded before the transfer course.

## The question

Can an older model supply useful structure for teaching the configuration that now processes input as changing activity? The control course reconstructed its entire predicate graph after each increment. This course instead inherits the older graph and learns refinements at its destination ports.

This is the first part of transferring a way of learning: reuse an established organization, locate where its interpretation fails, and teach a more specific distinction there. The refinement rule itself is supplied by the implementation. Learning to invent or replace that learning procedure is a further, unmeasured target. Neither structural inheritance nor ordinary state updates establish it.

## Matched lessons and selection

Start from the initial 5,201-byte English artifact. Use exactly the initial 389 ASDiv questions and the same three genuine-source increments of 5, 80 and 80 GSM8K questions as the [incremental course](INCREMENTAL_ENGLISH_PROTOCOL.md). Use its same 216 development questions and original 150-question ASDiv follow-up. Do not include the additional lessons from the questioning course. This makes a comparison of teaching mechanisms on the same lesson schedule possible.

For each teaching quantity pair, activate the older graph using the original question's input predicates. At each reached destination, collect the original source relation labels. Keep a destination unchanged when all those labels agree with its current preferred relation. Otherwise learn a local predicate tree at maximum depths 2, 4 and 8. Copy the older internal decisions and replace only the reached destination with that learned refinement. Keep unvisited destinations unchanged. Do not manufacture teacher questions or treat the older model's guesses as correct labels.

The procedure produces a new configuration; it does not mutate the teacher or retain training rows in the artifact. The new graph runs through the same current-activity input processor and signal substrate. Its learned predicates remain discrete. No continuous oscillator or quantum mechanism is introduced by this transfer.

At each increment, require candidates to retain every earlier correct teaching answer, measured against the published answer. Include keeping the previous configuration. Among admissible candidates, select highest development accuracy, then highest current teaching accuracy, then smallest artifact. Count all rejected candidates and their losses. This protects finite observed behavior and can still lose unseen capabilities.

## Outcome and controls

Freeze the final graph before revisiting ASDiv's original test bank. Compare with the initial configuration and the earlier reconstruction course. Both follow-ups are known project test banks, not new independent examinations. Report retained, lost and gained answers rather than relying on aggregate accuracy. A change is not promoted merely because it is bigger, uses inherited paths or fits its teaching examples better.

Record all teacher activations, refinement work, candidate evaluations, execution work, serialized bytes, CPU time, wall time, display time and available worker memory. Count the teacher, student, examples and candidates in the process memory measurement. Use one visible worker with Pause, Resume and Stop, the five-minute limit and observed 512 MiB ceiling. Each candidate has at most 60 million teaching work units; each problem has at most one million work units.

The wider proposal is to learn which learning transformations help in which situations. Establishing that would require many separate teaching tasks, a learned update controller, held-out task families, preservation checks and a comparison with the supplied controller. This course does not claim those results.
